# Estimating the Social Cost of Corporate Data Breaches

This repository contains the numerical implementation and analysis pipeline for the paper "Estimating the Social Cost of Corporate Data Breaches." 

Paper link: https://arxiv.org/abs/2603.21270

The paper connects 13 years of identity theft victimization data from the NCVS Identity Theft Supplement (ITS) with breach records from the Privacy Rights Clearinghouse (PRC), augmented with HHS breach disclosures and state-level breach filings, to build a social cost model of identity theft and a breach-to-victim conversion model. The code here harmonizes the survey data, cleans and augments the breach chronology, applies the social cost and conversion models, and runs the statistical tests and case studies that produce the paper's tables and figures.

```

```

`data/` and `plots/` are generated by running the code and are not checked into the repo.

## Data

This repository contains code only. The raw data has to be downloaded separately and placed under `data/raw/` before running the pipeline.

- **NCVS-ITS (2008-2021)**: six survey waves from ICPSR at [icpsr.umich.edu](https://www.icpsr.umich.edu). Download the raw TSV files for 2008, 2012, 2014, 2016, 2018, and 2021, and place each year's file at `data/raw/ITS/<year>/DS0001/`.
- **PRC Breach Chronology**: from [privacyrights.org](https://privacyrights.org). Place the SQLite database at `data/raw/PRC/PRC_DataBreachChronology_v2_202512/`.
- **HHS Breach Reports**: from the HHS OCR breach portal at [ocrportal.hhs.gov](https://ocrportal.hhs.gov). Place at `data/raw/PRC_supplements/`.
- **Maine and New Hampshire breach filings**: from the two states' Attorneys General offices. Place at `data/raw/PRC_supplements/`.
- **U.S. population data (age 16+)**: used by the saturation model, from the Bureau of Labor Statistics. Place at `data/raw/external/`.

`scripts/part2/race_table.py` also needs a Census API key, set as the `CENSUS_API_KEY` environment variable. A free key is available at [api.census.gov/data/key_signup.html](https://api.census.gov/data/key_signup.html).

## Running the pipeline

Run scripts in order, part1 through part6, from the repo root:

```
python scripts/part1/harmonize_its.py

python scripts/part2/calculate_social_cost.py
python scripts/part2/demographics_table.py
python scripts/part2/educational_profile_comparison.py
python scripts/part2/race_profile_comparison.py
python scripts/part2/race_table.py
python scripts/part2/social_cost_breach_vs_nonbreach.py
python scripts/part2/theft_type_analysis.py
python scripts/part2/hypothesis.py
python scripts/part2/incident_trends_plotter.py

python scripts/part3/load_raw_PRC_data.py
python scripts/part3/PRC_fill_in_health.py
python scripts/part3/find_nu.py
python scripts/part3/PRC_Maine_NH_regression.py

python scripts/part4/apply_saturation_model_exp.py

python scripts/part5/monthly_data_breach_conversion_beta.py
python scripts/part5/monthly_data_breach_conversion.py
python scripts/part5/breach_type_conversion.py
python scripts/part5/calculate_megabreach_cost_extended.py
python scripts/part5/sensitivity_alpha.py

python scripts/part6/wilcoxon_mega_breach_test.py
python scripts/part6/wilcoxon_placebo_test.py
```

Order matters in a few places beyond the part numbering. Within part2, `incident_trends_plotter.py` reads `calculate_social_cost.py`'s output. Within part3, `find_nu.py` reads `PRC_fill_in_health.py`'s output and prints an annual baseline value that is hand-copied into a constant in `PRC_Maine_NH_regression.py`, so `PRC_Maine_NH_regression.py` should be run last in part3. Within part5, `monthly_data_breach_conversion_beta.py` has to run first, since `calculate_megabreach_cost_extended.py`, `sensitivity_alpha.py`, and both part6 scripts all read its `conversion_data.csv` output.

## Config

**`harmonization_dictionary.json`** is the master ITS variable harmonization plan used throughout the pipeline. For each harmonized variable, it lists the source variable name for each survey year, recoding instructions mapping each year's original codes to a common set of categories, and cleaning rules such as max-value caps. It's read directly by `harmonize_its.py` and by several part2 scripts that need demographic category labels.

## Scripts

### Part 1: ITS Survey Harmonization

**`harmonize_its.py`** applies the harmonization dictionary to recode all six ITS waves onto a common set of variables, then builds a longitudinal victim dataset spanning 2008 to 2021. Produces both a victims-only dataset and an all-respondents dataset, since some later analyses need the full respondent population.

### Part 2: Social Cost Model and Demographic Analysis

**`calculate_social_cost.py`** computes the per-victim social cost of identity theft (out-of-pocket loss, legal cost, lost time cost, healthcare cost), producing the year-by-year cost table and demographic breakdowns by age, education, income, and race.

**`demographics_table.py`** builds weighted summaries of the victim population by year, age, sex, race, education, and income, the victim-side of the paper's victim-versus-Census demographic comparison.

**`educational_profile_comparison.py`** and **`race_profile_comparison.py`** compare victim profiles (theft type, discovery method, theft method) for high-education and White/Black/Asian victims respectively, against all other victims, to test whether overrepresentation is driven by exposure to specific kinds of fraud.

**`race_table.py`** pulls total U.S. population by race from the Census Bureau's ACS Data Profile, the general-population comparison point behind the victim race demographics.

**`social_cost_breach_vs_nonbreach.py`** compares social cost between breach-notified and non-notified victims, and separately between SSN-exposed and non-SSN-exposed breach victims.

**`theft_type_analysis.py`** builds a year-by-year summary of theft type, discovery method, and how information was obtained, the data behind the paper's incident summary table.

**`hypothesis.py`** tests two hypotheses about victim overrepresentation: whether the youngest age group is less vulnerable to digital theft than older groups, and whether age, education, income, and race are independently associated with victimization odds via logistic regression.

**`incident_trends_plotter.py`** is the main plotting script for part2, producing the paper's plots of theft method, theft type, discovery method, and social cost trends over time, plus social cost by demographic group.

### Part 3: PRC Breach Chronology Cleaning and Augmentation

**`load_raw_PRC_data.py`** loads the raw PRC database and deduplicates it, collapsing multiple state-level reports of the same breach event into one record.

**`PRC_fill_in_health.py`** supplements the deduplicated PRC base with HHS Breach Portal data: adding HHS breaches entirely absent from PRC as new rows, resolving conflicting record counts by keeping the higher value, and filling in incidents with an undisclosed count.

**`find_nu.py`** estimates the annual baseline for undisclosed PRC breach records, by breach type. Its result is printed to the terminal and hand-copied into a constant in `PRC_Maine_NH_regression.py`, it doesn't write a file.

**`PRC_Maine_NH_regression.py`** recovers national record counts for breaches that only have a state-level count, by regressing known national counts on matching Maine and New Hampshire filings, then applies the resulting multiplier to unmatched state incidents and imputes the remaining undisclosed PRC records using the annual baseline from `find_nu.py`.

### Part 4: Dynamic Saturation Model

**`apply_saturation_model_exp.py`** converts the augmented PRC record counts into an estimated number of unique individuals compromised each month, accounting for market saturation as the cumulative pool of exposed records grows.

### Part 5: Breach-to-Victim Conversion Model and Mega-Breach Cost Estimates

**`monthly_data_breach_conversion_beta.py`** is the paper's primary breach-to-victim conversion model: an alpha-discounted cumulative record supply, fit with a log-quadratic conversion rate curve over time.

**`monthly_data_breach_conversion.py`** is the saturation-model comparison to the primary model, using the saturation model's estimated unique-individual supply instead of the discounted record count.

**`breach_type_conversion.py`** computes the conversion rate restricted to HACK-type breaches, the type behind all four of the paper's mega-breach case studies.

**`calculate_megabreach_cost_extended.py`** computes the upper-bound (projected long-term) social cost for every sufficiently large breach in the augmented PRC dataset.

**`sensitivity_alpha.py`** checks whether the conversion model's results are sensitive to the discount factor, repeating the full pipeline at three different values and reporting both the fit coefficients and the resulting upper-bound social cost for each mega-breach case study.

### Part 6: Wilcoxon Signed-Rank Tests

**`wilcoxon_mega_breach_test.py`** tests whether the months following a mega-breach show a statistically significant increase in reported identity theft, swept across a range of discovery lags, run on both raw records exposed and the saturation model's unique-individual estimate.

**`wilcoxon_placebo_test.py`** is the placebo control: the identical test applied to months that do not meet the mega-breach threshold, to confirm the primary test's significance is tied to actual mega-breaches rather than a general trend.
